# Введение

В современных операционных системах с открытым исходным кодом системное программирование играет ключевую роль в обеспечении эффективного взаимодействия между программным обеспечением и аппаратными средствами. Особое место занимает разработка драйверов устройств ввода, функционирующих на уровне ядра и определяющих базовое поведение периферийных устройств.

Операционная система Linux предоставляет развитую архитектуру для разработки драйверов уровня ядра. Компьютерная мышь является одним из основных устройств ввода, от корректной работы которого зависит комфорт пользовательского взаимодействия с системой.

## Актуальность работы

Современные пользователи предъявляют различные требования к поведению мыши в зависимости от выполняемых задач:

- **В играх** требуется высокая точность при медленных движениях для прицеливания и быстрое перемещение курсора при резких движениях
- **В графических редакторах** необходима точность при детальной работе и скорость при навигации по большому холсту
- **При обычной работе** пользователь ожидает комфортного баланса между скоростью и точностью

Существующие решения имеют ограничения:

1. **Статические настройки DPI** — пользователь вынужден выбирать между скоростью и точностью
2. **Пользовательские решения** (libinput, xset) работают в пространстве пользователя и зависят от графической среды
3. **Аппаратные кнопки DPI** на игровых мышах требуют ручного переключения

Разработка драйвера уровня ядра с циклической автоподстройкой DPI позволяет автоматически адаптировать чувствительность мыши к характеру движений пользователя, обеспечивая:

- **Точность** при медленных движениях (низкий DPI)
- **Скорость** при быстрых движениях (высокий DPI)
- **Прозрачность** для пользовательских приложений
- **Независимость** от графической среды

## Образовательная ценность

Данная работа представляет образовательную ценность, поскольку требует глубокого понимания:

- Архитектуры ядра Linux и подсистемы ввода

- Создания виртуальных устройств ввода
- Алгоритмов вычисления скорости и фильтрации
- Принципов безопасной разработки кода на уровне ядра

## Практическая применимость

Драйвер с автоподстройкой DPI имеет практическое применение:

- **Игровая индустрия** — автоматическое переключение между точным прицеливанием и быстрым поворотом
- **Графический дизайн** — баланс между детальной работой и навигацией
- **Повседневная работа** — комфортное управление без ручной настройки

Реализация на уровне драйвера ядра обеспечивает минимальную задержку и работу в любом окружении (консоль, X11, Wayland, игры).

## Цель и задачи

**Целью** курсовой работы является разработка драйвера операционной системы Linux, реализующего циклическую автоподстройку DPI компьютерной мыши в зависимости от скорости движения.

# Глава 1. Теоретические основы

## 1.1. Понятие драйверов устройств и их роль в операционной системе

Драйвер устройства — это программный компонент операционной системы, обеспечивающий взаимодействие между аппаратным обеспечением и пользовательскими приложениями. Основная задача драйвера заключается в абстрагировании особенностей конкретного устройства и предоставлении стандартного интерфейса для работы с ним.

В операционных системах семейства Linux драйверы являются неотъемлемой частью ядра. Они позволяют операционной системе управлять различными аппаратными устройствами: клавиатурами, мышами, дисковыми накопителями, сетевыми адаптерами и другими периферийными устройствами.

### Архитектура ядра Linux

Linux имеет монолитное ядро с поддержкой загружаемых модулей. Драйверы могут быть:

- **Встроены** непосредственно в ядро
- **Загружаемые модули** (.ko файлы)

Драйверы устройств работают в **нулевом кольце защиты** (ring 0) с полным доступом к оборудованию и памяти. Это обеспечивает высокую производительность, но требует особой осторожности при разработке.

### Преимущества модулей ядра

Использование модулей ядра позволяет:

- Добавлять/удалять поддержку устройств без перезагрузки системы
- Упростить разработку и отладку драйверов
- Уменьшить размер основного ядра
- Динамически загружать драйверы при обнаружении устройств

## 1.2. Архитектура подсистемы ввода Linux

Ядро Linux включает специализированную подсистему для работы с устройствами ввода — **Input Subsystem**. Она предназначена для обработки событий от:

- Клавиатур
- Мышей и тачпадов
- Джойстиков и геймпадов
- Сенсорных экранов
- Графических планшетов

### Основные компоненты подсистемы ввода

Подсистема ввода состоит из трёх основных уровней:

1. **Input Device Drivers** — драйверы конкретных устройств (USB, PS/2, Bluetooth)
2. **Input Core** — ядро подсистемы, обрабатывающее события
3. **Event Handlers** — обработчики событий (evdev, mousedev, joydev)

### Путь события от устройства к приложению

```
Физическое устройство (USB мышь)
          ↓
  USB HID драйвер
          ↓
  Input Device (input_dev)
          ↓
    Input Core
          ↓
  Event Handlers (evdev)
          ↓
/dev/input/eventX
          ↓
Пользовательское приложение
```

### Интерфейс /dev/input/eventX

Для каждого зарегистрированного устройства ввода ядро создаёт файл `/dev/input/eventX`, через который приложения получают события. События передаются в виде структуры `input_event`:

```c
struct input_event {
    struct timeval time;  // Временная метка
    __u16 type;          // Тип события (EV_KEY, EV_REL, EV_ABS)
    __u16 code;          // Код события (KEY_A, REL_X, BTN_LEFT)
    __s32 value;         // Значение
};
```

### Типы событий мыши

Для компьютерной мыши используются следующие типы событий:

- **EV_REL** — относительное перемещение:
  - `REL_X` — движение по оси X
  - `REL_Y` — движение по оси Y
  - `REL_WHEEL` — прокрутка колеса
- **EV_KEY** — кнопки мыши:
  - `BTN_LEFT` — левая кнопка
  - `BTN_RIGHT` — правая кнопка
  - `BTN_MIDDLE` — средняя кнопка
- **EV_SYN** — синхронизация (завершение группы событий)

## 1.3. Механизм Input Handler

**Input Handler** — это механизм ядра Linux, позволяющий перехватывать и модифицировать события ввода на уровне ядра до того, как они попадут в пользовательское пространство.

### Принцип работы Input Handler

Input Handler регистрируется в подсистеме ввода и подписывается на события от определённых типов устройств. При поступлении события:

1. Событие генерируется драйвером физического устройства
2. Input Core передаёт событие всем зарегистрированным Handler'ам
3. Handler может:
   - **Пропустить** событие дальше (`return false`)
   - **Заблокировать** событие (`return true`)
   - **Модифицировать** событие
   - **Сгенерировать новые** события

### Структура Input Handler

```c
struct input_handler {
    void *private;                     // Приватные данные

    bool (*filter)(struct input_handle *handle,
                   unsigned int type,
                   unsigned int code,
                   int value);         // Фильтр событий

    int (*connect)(struct input_handler *handler,
                   struct input_dev *dev,
                   const struct input_device_id *id);  // Подключение

    void (*disconnect)(struct input_handle *handle); // Отключение

    const struct input_device_id *id_table;  // Таблица устройств
    const char *name;                        // Имя handler'а
};
```

### Преимущества Input Handler для задачи DPI

- Работает на уровне ядра — минимальная задержка
- Перехватывает события до evdev — полный контроль
- Может создавать виртуальные устройства ввода
- Независим от графической среды

## 1.4. Концепция DPI и акселерации мыши

### Что такое DPI

**DPI** (Dots Per Inch) — это параметр, определяющий чувствительность мыши. Он показывает, сколько пикселей курсор пройдёт на экране при физическом перемещении мыши на один дюйм.

- **Низкий DPI** (400-800) — высокая точность, медленное перемещение
- **Средний DPI** (800-1600) — баланс
- **Высокий DPI** (1600-3200+) — быстрое перемещение, меньше точности

### Проблема статических настроек

Пользователь вынужден выбирать компромисс:

- **Высокий DPI** — быстро перемещаться, но сложно точно навести курсор
- **Низкий DPI** — точные движения, но долго перемещаться на большие расстояния

### Концепция акселерации (ускорения)

**Акселерация мыши** — это изменение чувствительности в зависимости от скорости движения:

- **Медленное движение** → низкий коэффициент (точность)
- **Быстрое движение** → высокий коэффициент (скорость)

Это аналог Windows "Enhance pointer precision" или macOS acceleration.

### Циклическая автоподстройка DPI

В данной работе реализуется подход, где:

1. Драйвер **непрерывно измеряет скорость** движения мыши
2. **Автоматически выбирает** один из трёх уровней DPI:
   - **50%** — медленное движение (точность)
   - **100%** — среднее движение (норма)
   - **200%** — быстрое движение (скорость)
3. **Плавно переключается** между уровнями при изменении скорости

### Преимущества подхода

- Автоматическая адаптация к стилю работы
- Не требует ручного переключения кнопками
- Работает на уровне ядра (низкая задержка)
- Универсально для всех приложений

# Глава 2. Проектирование драйвера

## 2.1. Постановка задачи

Целью разработки является создание драйвера для компьютерной мыши, реализующего функцию циклической автоподстройки DPI в зависимости от скорости движения.

### Функциональные требования

Драйвер должен обеспечивать:

1. **Перехват событий мыши** — получение всех событий движения (REL_X, REL_Y)
2. **Вычисление скорости** — расчёт скорости движения на основе расстояния и времени между событиями
3. **Автоматический выбор DPI** — определение уровня DPI на основе скорости:
   - Скорость < 200 пикс/сек → DPI = 50%
   - Скорость 200-800 пикс/сек → DPI = 100%
   - Скорость > 800 пикс/сек → DPI = 200%
4. **Масштабирование движения** — умножение координат dx/dy на коэффициент DPI
5. **Создание виртуальной мыши** — отправка модифицированных событий через виртуальное устройство ввода
6. **Пробрасывание кнопок и колеса** — передача событий кнопок и колеса без изменений
7. **Логирование изменений DPI** — вывод в журнал ядра при смене уровня

### Нефункциональные требования

- **Производительность** — минимальная задержка обработки событий
- **Стабильность** — корректная работа без сбоев ядра
- **Совместимость** — работа с любыми приложениями и графическими средами
- **Автозагрузка** — автоматическая загрузка модуля при старте системы

### Ограничения

- Драйвер работает с любыми USB/PS/2 мышами (не привязан к конкретной модели)
- Пороговые значения скорости зашиты в код (не настраиваются динамически)
- Не предусмотрен интерфейс для пользовательской настройки через sysfs

## 2.2. Анализ возможных архитектурных решений

Для решения задачи автоподстройки DPI существует несколько подходов.

### 1. Решение в пространстве пользователя

**Подход:** демон читает события из `/dev/input/eventX`, вычисляет скорость и эмулирует новые события через `uinput`.

**Преимущества:**

- Простота разработки и отладки
- Не требует прав ядра
- Безопасность (падение демона не влияет на ядро)

**Недостатки:**

- Задержка из-за переключения контекста (user space ↔ kernel space)
- Зависимость от прав доступа к `/dev/input` и `/dev/uinput`
- Требует управления жизненным циклом демона (systemd service)
- Не работает до загрузки пользовательской сессии

### 2. Модификация libinput

**Подход:** патч libinput для добавления логики акселерации.

**Преимущества:**

- Интеграция с графическими средами (X11, Wayland)
- Поддержка настроек через GUI

**Недостатки:**

- Работает только в графических средах
- Не влияет на приложения, обращающиеся к `/dev/input` напрямую
- Сложность сопровождения патча при обновлениях libinput

### 3. Драйвер на основе Input Handler ✅

**Подход:** регистрация Input Handler в ядре, перехват событий от физической мыши, создание виртуальной мыши с модифицированными событиями.

**Преимущества:**

- Работает на уровне ядра — минимальная задержка
- Универсальность — работает в консоли, X11, Wayland, играх
- Прозрачность для приложений
- Автозагрузка через модули ядра

**Недостатки:**

- Сложность разработки и отладки
- Требует знаний программирования ядра
- Ошибка может привести к kernel panic

### Выбор решения

Для реализации выбран **подход с Input Handler**, поскольку он:

- Соответствует учебной цели (системное программирование)
- Обеспечивает минимальную задержку
- Работает универсально
- Демонстрирует глубокое понимание архитектуры Linux

## 2.3. Проектирование алгоритма работы драйвера

### Блок-схема алгоритма

```
Инициализация драйвера
         ↓
Регистрация Input Handler
         ↓
Создание виртуальной мыши
         ↓
┌─────────────────────────┐
│   Ожидание событий      │ ←──┐
└─────────────────────────┘    │
         ↓                      │
    Событие от мыши             │
         ↓                      │
┌──────────────────────────┐   │
│ Тип события?             │   │
└──────────────────────────┘   │
    │            │          │   │
 EV_REL      EV_KEY    EV_SYN  │
    │            │          │   │
    ↓            ↓          ↓   │
Накопление  Проброс   Обработка│
  dx, dy    кнопки    события  │
    │            │          │   │
    └────────────┴──────────┘   │
                  ↓              │
         Расчёт скорости         │
                  ↓              │
     Определение нового DPI      │
                  ↓              │
       Масштабирование dx, dy    │
                  ↓              │
   Отправка в виртуальную мышь   │
                  ↓              │
              Логирование        │
                  │              │
                  └──────────────┘
```

### Алгоритм вычисления скорости

1. При каждом событии EV_SYN сохраняются:
   - `dx`, `dy` — смещение с последнего события
   - `time` — временная метка события

2. Вычисление скорости:
   ```
   distance = |dx| + |dy|  (манхэттенское расстояние)
   time_diff = time_current - time_last  (в микросекундах)
   speed = distance * 1000000 / time_diff  (пикселей в секунду)
   ```

3. Если пауза > 1 секунда → используется средняя скорость 300 пикс/сек

### Алгоритм выбора DPI

```c
int calculate_dpi(int speed) {
    if (speed < SPEED_SLOW)        // < 200
        return 50;   // Точность
    else if (speed < SPEED_FAST)   // < 800
        return 100;  // Норма
    else
        return 200;  // Скорость
}
```

### Масштабирование координат

```c
scaled_dx = (dx * current_dpi) / 100;
scaled_dy = (dy * current_dpi) / 100;

input_report_rel(virt_mouse, REL_X, scaled_dx);
input_report_rel(virt_mouse, REL_Y, scaled_dy);
input_sync(virt_mouse);
```


## 3.3. Общий алгоритм работы драйвера

Драйвер функционирует по следующему алгоритму:

### 1. Инициализация (module_init)

- Регистрируется Input Handler в подсистеме ввода
- Устанавливается начальный DPI = 100%
- Инициализируется временная метка

### 2. Подключение к устройству (mouse_connect)

При обнаружении мыши:

- Создаётся виртуальное устройство ввода (input_dev)
- Настраиваются поддерживаемые события (REL_X, REL_Y, REL_WHEEL, кнопки)
- Регистрируется виртуальная мышь в подсистеме ввода
- Захватывается физическая мышь (input_grab_device) для эксклюзивного доступа

### 3. Обработка событий (event_filter)

Для каждого события от физической мыши:

**Тип EV_REL:**

- `REL_X` → накапливается в `dx`
- `REL_Y` → накапливается в `dy`
- `REL_WHEEL` → пробрасывается в виртуальную мышь без изменений

**Тип EV_KEY:**

- Пробрасываются все кнопки (BTN_LEFT, BTN_RIGHT, BTN_MIDDLE) без изменений

**Тип EV_SYN:**

- Вычисляется скорость: `speed = (|dx| + |dy|) * 1000000 / time_diff`
- Определяется новый DPI: `new_dpi = calculate_dpi(speed)`
- Если DPI изменился → логируется изменение
- Масштабируются координаты: `scaled_dx = dx * dpi / 100`
- Отправляются модифицированные события в виртуальную мышь
- Сбрасываются `dx`, `dy`, обновляется `last_time`

### 4. Отключение (mouse_disconnect)

При отключении мыши или выгрузке модуля:

- Освобождается захват физической мыши
- Удаляется виртуальное устройство ввода
- Освобождается память

## 3.4. Реализация ключевых функций

### Вычисление скорости (calc_speed)

Функция не используется в финальной версии. Расчёт скорости происходит напрямую в `event_filter`:

```c
ktime_t now = ktime_get();
s64 time_diff_us = ktime_to_us(ktime_sub(now, driver_data.last_time));

if (time_diff_us > 0 && time_diff_us < 1000000) {
    int distance = abs(dx) + abs(dy);
    speed = (int)((s64)distance * 1000000 / time_diff_us);
} else {
    speed = 300;  // Пауза или первое событие
}
```

**Особенности:**

- Используется манхэттенское расстояние (|dx| + |dy|) вместо Евклидова для скорости вычисления
- Проверка `time_diff_us < 1000000` исключает паузы > 1 секунды
- При паузе используется средняя скорость 300 пикс/сек

### Определение DPI (calculate_dpi)

```c
static int calculate_dpi(int speed)
{
    if (speed < SPEED_SLOW)
        return 50;   // < 200: медленно
    else if (speed < SPEED_FAST)
        return 100;  // 200-800: средне
    else
        return 200;  // > 800: быстро
}
```

Константы:

```c
#define SPEED_SLOW  200
#define SPEED_FAST  800
```

### Фильтр событий (event_filter)

Центральная функция драйвера. Обрабатывает все события от физической мыши:

**Псевдокод:**

```
function event_filter(type, code, value):
    if type == EV_REL:
        if code == REL_X:
            dx = value
        else if code == REL_Y:
            dy = value
        else:
            // Колесико - проброс
            send_to_virtual_mouse(code, value)
        return true  // Блокировать оригинальное событие

    if type == EV_KEY:
        // Кнопки - проброс
        send_to_virtual_mouse(code, value)
        return true

    if type == EV_SYN and code == SYN_REPORT:
        if dx == 0 and dy == 0:
            return true

        // Вычисление скорости
        now = get_time()
        time_diff = now - last_time
        distance = |dx| + |dy|
        speed = distance / time_diff * 1000000

        // Определение DPI
        new_dpi = calculate_dpi(speed)
        if new_dpi != current_dpi:
            log("CHANGE " + current_dpi + "% -> " + new_dpi + "%")
            current_dpi = new_dpi

        // Масштабирование
        scaled_dx = dx * current_dpi / 100
        scaled_dy = dy * current_dpi / 100

        // Отправка
        send_to_virtual_mouse(REL_X, scaled_dx)
        send_to_virtual_mouse(REL_Y, scaled_dy)
        sync_virtual_mouse()

        // Обновление состояния
        last_time = now
        dx = dy = 0

        return true

    return false
```

### Создание виртуальной мыши (create_virtual_mouse)

```c
static int create_virtual_mouse(void)
{
    driver_data.virt_mouse = input_allocate_device();
    if (!driver_data.virt_mouse)
        return -ENOMEM;

    driver_data.virt_mouse->name = "Virtual Mouse (Accelerated)";
    driver_data.virt_mouse->id.bustype = BUS_VIRTUAL;
    driver_data.virt_mouse->id.vendor = 0x1234;
    driver_data.virt_mouse->id.product = 0x5678;

    // Поддержка движения
    set_bit(EV_REL, driver_data.virt_mouse->evbit);
    set_bit(REL_X, driver_data.virt_mouse->relbit);
    set_bit(REL_Y, driver_data.virt_mouse->relbit);
    set_bit(REL_WHEEL, driver_data.virt_mouse->relbit);

    // Поддержка кнопок
    set_bit(EV_KEY, driver_data.virt_mouse->evbit);
    set_bit(BTN_LEFT, driver_data.virt_mouse->keybit);
    set_bit(BTN_RIGHT, driver_data.virt_mouse->keybit);
    set_bit(BTN_MIDDLE, driver_data.virt_mouse->keybit);

    return input_register_device(driver_data.virt_mouse);
}
```

**Ключевые моменты:**

- `BUS_VIRTUAL` — виртуальное устройство, не привязано к физической шине
- Vendor/Product ID произвольные (0x1234/0x5678)
- Регистрируются все необходимые события для полной эмуляции мыши

Разработанное решение корректно осуществляет автоматическую подстройку чувствительности мыши в зависимости от характера движений, что подтверждено тестированием в различных сценариях. Драйвер работает на уровне ядра, обеспечивая универсальность и минимальную задержку.

Таким образом, курсовая работа не только закрепляет теоретические знания, но и формирует ценный практический опыт, необходимый для дальнейшей деятельности в области системного программирования, разработки драйверов и анализа низкоуровневых компонентов операционной системы Linux.

# Приложения

## Приложение 1. Исходный код драйвера (mouse_accel.c)

```c
/*
 * Драйвер мыши с акселерацией (как в Windows)
 * Логика: Быстрое движение = Высокий DPI
 */

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/input.h>
#include <linux/slab.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Student");
MODULE_DESCRIPTION("Mouse Acceleration Driver");
MODULE_VERSION("5.0");

/* === НАСТРОЙКИ === */
#define SPEED_SLOW  200    // Медленное движение: < 200 пикс/сек
#define SPEED_FAST  800    // Быстрое движение: > 800 пикс/сек

/* === ГЛОБАЛЬНЫЕ ПЕРЕМЕННЫЕ === */
static struct {
    struct input_handler handler;
    struct input_dev *virt_mouse;    // Виртуальная мышь

    // Для расчета скорости
    int last_dx, last_dy;            // Последнее движение
    ktime_t last_time;               // Время последнего события

    int current_dpi;                 // Текущий DPI: 50, 100, 200
} driver_data;

/* === ОПРЕДЕЛЕНИЕ DPI ПО СКОРОСТИ === */
static int calculate_dpi(int speed)
{
    if (speed < SPEED_SLOW)
        return 50;   // Медленно → точность
    else if (speed < SPEED_FAST)
        return 100;  // Средняя скорость
    else
        return 200;  // Быстро → скорость
}

/* === ОБРАБОТКА СОБЫТИЙ === */
static bool event_filter(struct input_handle *handle, unsigned int type,
                         unsigned int code, int value)
{
    static int dx = 0, dy = 0;

    /* Движение мыши */
    if (type == EV_REL) {
        if (code == REL_X) {
            dx = value;
        } else if (code == REL_Y) {
            dy = value;
        } else {
            // Колесико - пробрасываем
            if (driver_data.virt_mouse) {
                input_report_rel(driver_data.virt_mouse, code, value);
                input_sync(driver_data.virt_mouse);
            }
        }
        return true;  // Блокируем оригинальное событие
    }

    /* Кнопки мыши */
    if (type == EV_KEY) {
        if (driver_data.virt_mouse) {
            input_report_key(driver_data.virt_mouse, code, value);
            input_sync(driver_data.virt_mouse);
        }
        return true;
    }

    /* Синхронизация - обрабатываем событие */
    if (type == EV_SYN && code == SYN_REPORT) {
        ktime_t now;
        s64 time_diff_us;
        int distance, speed, new_dpi;
        int scaled_dx, scaled_dy;

        // Если мышь не двигалась - ничего не делаем
        if (dx == 0 && dy == 0)
            return true;

        // Текущее время
        now = ktime_get();

        // Расчет скорости
        time_diff_us = ktime_to_us(ktime_sub(now, driver_data.last_time));

        if (time_diff_us > 0 && time_diff_us < 1000000) {  // Максимум 1 секунда
            // Расстояние = |dx| + |dy|
            distance = abs(dx) + abs(dy);

            // Скорость = пиксели / секунда
            speed = (int)((s64)distance * 1000000 / time_diff_us);
        } else {
            // Пауза или первое событие - используем среднюю скорость
            speed = 300;
        }

        // Определяем новый DPI
        new_dpi = calculate_dpi(speed);

        // Если DPI изменился - логируем
        if (new_dpi != driver_data.current_dpi) {
            pr_info("mouse_dpi: CHANGE %d%% -> %d%% (speed=%d px/s)\n",
                    driver_data.current_dpi, new_dpi, speed);
            driver_data.current_dpi = new_dpi;
        }

        // Масштабируем движение
        scaled_dx = (dx * driver_data.current_dpi) / 100;
        scaled_dy = (dy * driver_data.current_dpi) / 100;

        // Отправляем в виртуальную мышь
        if (driver_data.virt_mouse) {
            input_report_rel(driver_data.virt_mouse, REL_X, scaled_dx);
            input_report_rel(driver_data.virt_mouse, REL_Y, scaled_dy);
            input_sync(driver_data.virt_mouse);
        }

        // Сохраняем для следующего раза
        driver_data.last_dx = dx;
        driver_data.last_dy = dy;
        driver_data.last_time = now;

        // Сбрасываем накопленные значения
        dx = dy = 0;

        return true;
    }

    return false;
}

/* === ПОДКЛЮЧЕНИЕ К МЫШИ === */
static int mouse_connect(struct input_handler *handler, struct input_dev *dev,
                         const struct input_device_id *id)
{
    struct input_handle *handle;
    int err;

    // Игнорируем виртуальные устройства
    if (dev->id.bustype == BUS_VIRTUAL)
        return -ENODEV;

    // Только мыши с координатами
    if (!test_bit(EV_REL, dev->evbit) || !test_bit(REL_X, dev->relbit))
        return -ENODEV;

    handle = kzalloc(sizeof(*handle), GFP_KERNEL);
    if (!handle)
        return -ENOMEM;

    handle->dev = dev;
    handle->handler = handler;
    handle->name = "mouse_accel";

    err = input_register_handle(handle);
    if (err)
        goto err_free;

    err = input_open_device(handle);
    if (err)
        goto err_unreg;

    // Захватываем эксклюзивно
    err = input_grab_device(handle);
    if (err)
        pr_warn("mouse_dpi: Cannot grab %s (not critical)\n", dev->name);

    pr_info("mouse_dpi: Connected to %s\n", dev->name);
    return 0;

err_unreg:
    input_unregister_handle(handle);
err_free:
    kfree(handle);
    return err;
}

/* === ОТКЛЮЧЕНИЕ ОТ МЫШИ === */
static void mouse_disconnect(struct input_handle *handle)
{
    pr_info("mouse_dpi: Disconnected from %s\n", handle->dev->name);
    input_close_device(handle);
    input_unregister_handle(handle);
    kfree(handle);
}

/* === ТАБЛИЦА УСТРОЙСТВ === */
static const struct input_device_id mouse_ids[] = {
    {
        .flags = INPUT_DEVICE_ID_MATCH_EVBIT | INPUT_DEVICE_ID_MATCH_RELBIT,
        .evbit = { BIT_MASK(EV_REL) },
        .relbit = { BIT_MASK(REL_X) | BIT_MASK(REL_Y) },
    },
    { }
};

MODULE_DEVICE_TABLE(input, mouse_ids);

/* === HANDLER === */
static struct input_handler mouse_handler = {
    .filter     = event_filter,
    .connect    = mouse_connect,
    .disconnect = mouse_disconnect,
    .name       = "mouse_accel",
    .id_table   = mouse_ids,
};

/* === СОЗДАНИЕ ВИРТУАЛЬНОЙ МЫШИ === */
static int create_virtual_mouse(void)
{
    int err;

    driver_data.virt_mouse = input_allocate_device();
    if (!driver_data.virt_mouse)
        return -ENOMEM;

    driver_data.virt_mouse->name = "Virtual Mouse (Accelerated)";
    driver_data.virt_mouse->id.bustype = BUS_VIRTUAL;
    driver_data.virt_mouse->id.vendor = 0x1234;
    driver_data.virt_mouse->id.product = 0x5678;

    // Поддержка движения
    set_bit(EV_REL, driver_data.virt_mouse->evbit);
    set_bit(REL_X, driver_data.virt_mouse->relbit);
    set_bit(REL_Y, driver_data.virt_mouse->relbit);
    set_bit(REL_WHEEL, driver_data.virt_mouse->relbit);

    // Поддержка кнопок
    set_bit(EV_KEY, driver_data.virt_mouse->evbit);
    set_bit(BTN_LEFT, driver_data.virt_mouse->keybit);
    set_bit(BTN_RIGHT, driver_data.virt_mouse->keybit);
    set_bit(BTN_MIDDLE, driver_data.virt_mouse->keybit);

    err = input_register_device(driver_data.virt_mouse);
    if (err) {
        input_free_device(driver_data.virt_mouse);
        driver_data.virt_mouse = NULL;
        return err;
    }

    pr_info("mouse_dpi: Virtual mouse created\n");
    return 0;
}

/* === ИНИЦИАЛИЗАЦИЯ МОДУЛЯ === */
static int __init mouse_accel_init(void)
{
    int err;

    pr_info("=========================================\n");
    pr_info("mouse_dpi: Acceleration Driver v5.0\n");
    pr_info("mouse_dpi: Logic: Fast = High DPI\n");
    pr_info("mouse_dpi: Slow < %d < Fast < %d < Very Fast\n",
            SPEED_SLOW, SPEED_FAST);
    pr_info("=========================================\n");

    // Инициализация
    memset(&driver_data, 0, sizeof(driver_data));
    driver_data.current_dpi = 100;           // Стартовый DPI
    driver_data.last_time = ktime_get();     // Текущее время

    // Создаем виртуальную мышь
    err = create_virtual_mouse();
    if (err) {
        pr_err("mouse_dpi: Failed to create virtual mouse: %d\n", err);
        return err;
    }

    // Регистрируем обработчик
    err = input_register_handler(&mouse_handler);
    if (err) {
        pr_err("mouse_dpi: Failed to register handler: %d\n", err);
        input_unregister_device(driver_data.virt_mouse);
        return err;
    }

    pr_info("mouse_dpi: Driver loaded successfully\n");
    return 0;
}

/* === ВЫГРУЗКА МОДУЛЯ === */
static void __exit mouse_accel_exit(void)
{
    pr_info("mouse_dpi: Unloading driver\n");

    // Отключаем обработчик
    input_unregister_handler(&mouse_handler);

    // Удаляем виртуальную мышь
    if (driver_data.virt_mouse) {
        input_unregister_device(driver_data.virt_mouse);
        driver_data.virt_mouse = NULL;
    }

    pr_info("mouse_dpi: Driver unloaded\n");
}

module_init(mouse_accel_init);
module_exit(mouse_accel_exit);
```

## Приложение 2. Makefile

```makefile
# Makefile для драйвера мыши с акселерацией

obj-m += mouse_accel.o

KDIR := /lib/modules/$(shell uname -r)/build

all:
	@echo "========================================="
	@echo "Сборка драйвера с АКСЕЛЕРАЦИЕЙ v5.0"
	@echo "Логика: Быстро = ВЫСОКИЙ DPI"
	@echo "========================================="
	$(MAKE) -C $(KDIR) M=$(PWD) modules
	@echo ""
	@echo "✅ Собрано: mouse_accel.ko"
	@echo ""
	@echo "Команды:"
	@echo "  sudo insmod mouse_accel.ko   - Загрузить"
	@echo "  sudo rmmod mouse_accel       - Выгрузить"
	@echo "  dmesg | tail -50             - Посмотреть логи"

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

.PHONY: all clean
```

## Приложение 3. Инструкция по установке и использованию

### Сборка

```bash
make
```

### Загрузка модуля

```bash
sudo insmod mouse_accel.ko
```

### Просмотр логов

```bash
dmesg | grep mouse_dpi
```

Или в реальном времени:

```bash
dmesg -w | grep mouse_dpi
```

### Выгрузка модуля

```bash
sudo rmmod mouse_accel
```

### Установка для автозагрузки

```bash
# 1. Копирование модуля
sudo cp mouse_accel.ko /lib/modules/$(uname -r)/kernel/drivers/input/

# 2. Обновление зависимостей
sudo depmod -a

# 3. Настройка автозагрузки
echo "mouse_accel" | sudo tee /etc/modules-load.d/mouse_dpi.conf

# 4. Перезагрузка
sudo reboot
```

### Проверка автозагрузки

После перезагрузки:

```bash
lsmod | grep mouse_accel
dmesg | grep mouse_dpi
```

### Удаление из автозагрузки

```bash
sudo rm /etc/modules-load.d/mouse_dpi.conf
sudo rm /lib/modules/$(uname -r)/kernel/drivers/input/mouse_accel.ko
sudo depmod -a
```
